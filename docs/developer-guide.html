1 هيكل المشروع

sooqify-image-updater/ ├── app/ │ ├── main.py نقطة التشغيل + واجهة pywebview + خيط الرفع الخلفي │ ├── config.py إعدادات أول تشغيل + اكتشاف وضع المطوّر │ ├── scanner.py فحص المجلدات وقراءة product_info.txt │ ├── uploader.py رفع الصور + البحث الآمن والتحقق من الهوية │ ├── sync_client.py التواصل مع sync.php (نفس نظام AlphaCode) │ ├── logger_setup.py سجل طرفية ملوّن │ └── ui/ index.html + styles.css + app.js ├── dev_tools/ أداة فحص سلوك الرفع (وضع المطوّر فقط) ├── build/ ملف PyInstaller ├── .github/workflows/ بناء exe تلقائي على GitHub Actions ├── docs/ هذا الدليل + دليل المستخدم └── assets/ أيقونة التطبيق

2 وضع المطوّر

يُفعَّل تلقائياً لما يكون OperatorName بالإعدادات يساوي yousef (بأي حالة أحرف). يظهر شارة "وضع المطوّر" بأعلى الواجهة.

الحد الأقصى للدفعة (BatchLimit) الافتراضي بلا نهاية — يُضبط من شاشة الإعدادات.

3 المحددات الحقيقية (Selectors) — صفحة سوقيفاي

العنصر المحدد
الصورة الرئيسية #customFileEg1
صور المعرض input.spartan_image_input (آخر حقل فاضٍ دائماً)
زر الحفظ زر بنص "اعتماد"، type=submit
صندوق البحث (القائمة) #datatableSearch
عمود التحقق (العرض) عمود "العلامات" بجدول التسعير

الحفظ الناجح يُعيد التوجيه لـ /admin/item/list — هذا دليل النجاح المعتمد بالكود.

4 مشكلة بروفايل Chrome

Chrome يرفض تفعيل التحكم البرمجي (CDP) على مجلد البروفايل الافتراضي مباشرة (قيد أمني من جوجل: "DevTools remote debugging requires a non-default data directory"). الحل المطبَّق بـ main.py: نسخ بيانات البروفايل لمجلد مؤقت (بدون Cache لتسريع النسخ) وتشغيل Playwright على النسخة.

5 البناء إلى exe

لا بناء محلي يدوي — GitHub Actions يبنيه تلقائياً على Windows حقيقي عند أي رفعة لـ main أو أي Tag يبدأ بـ v:

git tag v1.0.0
git push origin v1.0.0

الملف الناتج يظهر بصفحة Releases بالمستودع، جاهز للتنزيل مباشرة.

6 حذف الصور السابقة (Gallery)

في صفحة تعديل المنتج، واجهة Spartan Multi Image Picker تعرض الصور السابقة كعناصر تحتوي على زر حذف. لحذف الصور السابقة قبل الرفع الجديد بدون التكرار وإضافة صور متراكمة، يتم البحث عن جميع العناصر المطابقة للمُحدّد a.spartan_remove_row، ويتم النقر عليها برمجيًا. وبما أن هذه العملية تتم عبر AJAX أو إعادة توجيه محلية داخل الإضافة، يجب إضافة مهلة قصيرة جداً (مثلاً 100-200ms) بعد كل نقرة للسماح لـ DOM بالتحديث ولتجنب أخطاء الشبكة.

7 سكربت سجل الكومتات

build_history.sh بجذر المشروع يقسّم كل التعديلات لكومتات صغيرة منطقية بتواريخ موزّعة، بنفس منهجية مشروع AlphaCode الرئيسي. شغّله من جذر المستودع بعد أي دفعة تعديلات جديدة.
